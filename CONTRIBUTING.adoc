= Contributing to Mobile NixOS

You don't need to write code to help contributing with Mobile NixOS.

As Mobile NixOS is a superset on top of NixOS, you should read the link:https://github.com/NixOS/nixpkgs/blob/master/CONTRIBUTING.md[
contributing guidelines] of the NixOS project. Many of the points apply just
the same with Mobile NixOS.

== “AI”-assisted contributions

[NOTE]
====
Using pre-existing *boilerplate*, *snippets*, or *syntax suggestions* from your IDE are not considered as “AI”-assisted changes.
====

While we strongly prefer human-authored, non-LLM code and human-verified solutions, we also value pragmatic progress: if an important feature, device adaptation, or driver enablement would otherwise not exist at all without LLM assistance, well-audited and properly tested LLM-assisted contributions are acceptable.

When submitting LLM-assisted work:

 - *Be transparent*: Clearly disclose that LLMs were used to draft or assist the contribution.
 - *Rigorous scrutiny & verification*: Ensure all generated code is thoroughly audited, builds cleanly, and is verified on real hardware or test suites rather than relying on untested hallucinations or dummy mockups.
 - *Upstream & patch focus*: Prefer minimal, clean patches against upstream sources rather than unverified, vendored code dumps.

Contributions should clearly identify the responsible person in the commit information (`Committer`, `Author`, `Signed-off-by`, and `Co-authored-by` fields).

If you had help from automated “AI”-generation in part or all of your contribution, please let us know upfront.
It will be evaluated on a case-by-case basis with a focus on real-world functionality, reproducibility, and code quality.
We value honesty and transparency above all.

The same applies to repository interactions: automated, generic AI summaries without substance or verification are not welcome, but thoughtful, human-curated contributions that solve real problems are welcome.

Machine translation of prose for accessibility and localization is always welcome, provided it is noted.

== Opening issues

Issues you face when using or working with Mobile NixOS should be filed on
link:https://github.com/mobile-nixos/mobile-nixos/issues[the project's issue tracker].

First verify an existing, open, and recent issue matching your exact problem
doesn't already exist. In case of doubt, always open a new issue. Sometimes
vaguely reported symptoms are from different sources and it is easier to manage
when different issues are opened.

When describing the issues you face, please provide the most information you
can. For sharing logs, please share them as link:https://gist.github.com/[Gists]
so the issue does not get bogged down.

== Packaging software

Unless it is related to the abstraction of device specifics, packaging should
be done upstream at the link:https://github.com/NixOS/nixpkgs[Nixpkgs] project.

Mobile NixOS is a superset of NixOS, all the software that is in NixOS is
available for Mobile NixOS.
